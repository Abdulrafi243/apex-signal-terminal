# v1.0.4 — Twelve Data rate-limit protection

- Added server-side Forex candle cache.
- Historical Forex candles are no longer refetched on every UI/analysis poll.
- Twelve Data HTTP 429 activates a cooldown/backoff instead of repeated API hammering.
- If cached candles exist, the chart and analysis continue from cache during a rate-limit window.
- Raw upstream errors and API-key-bearing URLs are never returned to the frontend.
- Frontend now shows a short clean message only when no cached candles exist.
- Forex provider status exposes READY / RATE_LIMITED / NOT_CONFIGURED and retry seconds.
- WebSocket streaming remains the live-price path; REST is used mainly for history/seed candles.
- Live signal safety rules still prevent stale/missed setups from becoming fresh LIVE alerts.
