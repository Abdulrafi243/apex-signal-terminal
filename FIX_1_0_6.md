# v1.0.6 — Stability + Fresh Signal Release

## Fixed
- News page no longer renders blank; missing page helpers were restored and provider-unavailable states render safely.
- Economic Calendar no longer renders blank and clearly shows provider-not-configured/unavailable states.
- Backtesting page no longer renders blank if one optional validation call fails; modules settle independently.
- Added a React Error Boundary so a single page render error cannot white-screen the terminal.
- Signal history now shows TP1, TP2 and TP3 (profit targets) next to Entry and SL.
- Market Scanner now shows Entry and TP1.
- Current Signal refresh reduced to 3 seconds.
- Added STALE_SETUP guard: an order-block setup older than 12 bars is not advertised as a new live signal.
- Rejected polling snapshots are no longer persisted as signals; signal history is cleaner and focused on actionable/review setups.
- Added signal-history deduplication to prevent the same setup being written every poll.
- Forex WebSocket live candle now updates the backend candle cache used by the Signal Engine.
- Binance WebSocket live candle is also merged into analysis reads, aligning chart and signal current price.
- Existing v1.0.5 connectivity fallback and v1.0.4 rate-limit cache remain enabled.

## Signal semantics
- LIVE: entry is actionable now and all guards pass.
- REVIEW: setup is forming/waiting, or a protective guard blocks live authorization.
- NO_TRADE: missed, TP already reached, invalidated, stale setup, or rejected conditions.
- A stale/missed setup is never converted into a chase entry. The engine waits for a fresh setup from current market data.
